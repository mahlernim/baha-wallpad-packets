# 난방 노드 `40 90`

상위 문서: [README](../README.md)  
바로 가기: [프로토콜 개요](protocol-overview.md) | [하드웨어](hardware.md) | [거실 조명 `10 04`](lighting-node-10-04.md) | [현관 / 일괄소등 `1F 0F`](master-switch-node-1f0f.md) | [참고 자료](../reference/README.md)

`40 90`은 BAHA 버스의 난방 상태 조회·제어 노드다. 아래 내용은 한 설치 환경의 실측 결과이며, Honeywell / Resideo 제품군 전체의 규격은 아니다. 제조사 설명서의 통신 구조와 모델별 동작은 [난방 시스템](heating-system.md)을 참고한다.

## 조회 / 응답 쌍

```text
02 40 90 01 00 D3 00 -> 02 40 90 81 ...
02 40 90 05 00 D7 00 -> 02 40 90 85 ...
```

확인된 응답 의미:

- `81` = 현재 측정 온도 테이블
- `85` = 목표 설정 온도 테이블

## 방 순서

실측한 `DL=06` 응답은 타입 1바이트와 방 5바이트로 구성된다. 아래 방 이름과 순서는 시험 환경의 매핑이며 다른 설치에서는 달라질 수 있다.

| 슬롯 | 방 |
| --- | --- |
| `1` | 거실 |
| `2` | 안방 |
| `3` | 놀이방 |
| `4` | 서재 |
| `5` | 침실 |

## 값 인코딩

일반 상태 값:

```text
0x80 + temperature_celsius
```

외출모드 값:

```text
0xC0 + temperature_celsius
```

비트 단위로는 다음과 같이 해석할 수 있다.

```text
temperature_celsius = value & 0x3F
away                 = (value & 0x40) != 0
normal value         = 0x80 | temperature_celsius
away value           = 0xC0 | temperature_celsius
```

현재 온도 `81`과 목표 온도 `85`에 같은 해석을 적용한다. 외출 상태에서 `0x80`만 빼면 온도가 `64 C` 높게 계산되므로 `value & 0x3F`를 사용한다.

예:

```text
93 = 일반 설정온도 19 C
94 = 일반 설정온도 20 C
95 = 현재 또는 설정온도 21 C
96 = 현재 또는 설정온도 22 C
97 = 현재 또는 설정온도 23 C
CA = 외출모드 설정온도 10 C
D5 = 외출모드 코드 21 C
D6 = 외출모드 코드 22 C
D7 = 외출모드 코드 23 C
```

2026-07-29 놀이방만 외출로 전환했을 때 다음 값을 확인했다.

| 모드 | `81` 현재 온도 바이트 | 해석 | `85` 목표 온도 바이트 | 해석 |
| --- | --- | --- | --- | --- |
| 일반 | `A0` | `32 C` | `93` | `19 C` |
| 외출 | `E0` | `32 C` | `CA` | `10 C` |

`A0 -> E0`에서 온도값은 그대로이고 외출 비트 `0x40`만 추가된다.

## 응답 세부 타입

세부 타입은 `DL=06` 바로 뒤의 바이트다.

확인된 의미:

- `02` = 모든 방이 외출모드인 상태는 아님
- `03` = 모든 방이 외출모드 상태

전부 외출모드인 경우 예:

```text
81: 02 40 90 81 06 03 D7 D6 D5 D6 D5 81 00
85: 02 40 90 85 06 03 CA CA CA CA CA 98 00
```

## 액션 / 쓰기 형식

확인된 난방 쓰기 형식:

```text
02 40 90 02 06 T0 T1 T2 T3 T4 T5 CS 00
```

- `T1..T5`는 5개 방 슬롯
- 방 바이트가 `00`이면 해당 방은 변경하지 않음

## 확인된 `T0` 의미

| `T0` | 의미 |
| --- | --- |
| `00` | 외출 설정·해제와 일반 목표 온도 쓰기 |
| `02` | 외출 중인 방을 저장된 일반 설정온도로 복귀. 새 목표 온도는 적용하지 않음 |

## 확인된 방별 액션

외출모드 설정:

```text
거실 외출모드   = 02 40 90 02 06 00 C0 00 00 00 00 16 00
안방 외출모드   = 02 40 90 02 06 00 00 C0 00 00 00 16 00
놀이방 외출모드 = 02 40 90 02 06 00 00 00 C0 00 00 16 00
서재 외출모드   = 02 40 90 02 06 00 00 00 00 C0 00 16 00
침실 외출모드   = 02 40 90 02 06 00 00 00 00 00 C0 16 00
```

위 `C0` 단일 슬롯 프레임은 월패드가 직접 보내는 외출 명령이다. 2026-07-30 능동 시험에서는 `CA`를 직접 넣은 명령도 놀이방 외출 설정으로 수락됐다.

```text
놀이방 외출 10 C = 02 40 90 02 06 00 00 00 CA 00 00 1C 00
```

직접 쓰기를 시험한 외출 목표값은 `CA`(`10 C`)뿐이다. 다른 `0xC0 | temperature` 값의 수락 여부는 미확인이다.

외출모드 해제:

```text
거실 외출모드 해제   = 02 40 90 02 06 00 80 00 00 00 00 56 00
안방 외출모드 해제   = 02 40 90 02 06 00 00 80 00 00 00 56 00
놀이방 외출모드 해제 = 02 40 90 02 06 00 00 00 80 00 00 56 00
서재 외출모드 해제   = 02 40 90 02 06 00 00 00 00 80 00 56 00
침실 외출모드 해제   = 02 40 90 02 06 00 00 00 00 00 80 56 00
```

목표 온도를 지정하며 일반 모드로 전환하는 명령도 확인했다.

```text
놀이방 일반 19 C = 02 40 90 02 06 00 00 00 93 00 00 45 00
```

## 방별 목표 온도 쓰기

일반 목표 온도는 `T0=00`으로 두고 한 방의 바이트만 지정한다.

```text
02 40 90 02 06 00 T1 T2 T3 T4 T5 CS 00
```

예:

```text
안방 21 C = 02 40 90 02 06 00 00 95 00 00 00 43 00
```

확인된 동작:

- 일반 상태에서는 저장된 목표 온도를 바꾼다.
- 외출 상태에서는 외출을 해제하고 새 목표 온도를 적용한다.

기존 실측 기록의 직접 설정 범위:

```text
5 C ~ 35 C
```

## UI의 "꺼짐" 해석

관찰한 BAHA UI의 `off`는 다음 상태에 대응한다.

```text
외출모드 / 관찰된 목표 설정온도 10 C
```

이 경로에서 별도의 완전 정지 상태는 확인하지 못했으며, 저온에서 실제 난방이 자동 가동되는지도 시험하지 않았다. 온도조절기의 `OFF`와 앱의 `off`는 모델마다 의미가 다르므로 [설명서별 비교](heating-system.md)를 함께 참고한다.
